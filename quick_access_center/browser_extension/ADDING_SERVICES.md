# Подключение своих сервисов к автовходу

Автовход работает для **явного списка** адресов. Список задаётся в двух местах —
на сервере панели и в расширении — и обязан совпадать. Пароль из Vault выдаётся
один раз, на 45 секунд и только точному HTTPS-адресу из этого списка.

| Где | Файл | Что задаёт |
| --- | --- | --- |
| Панель (сервер) | `vault_control/vault.env`, ключ `VAULT_AUTOLOGIN_SITES` | каким карточкам разрешено просить пароль |
| Расширение | `browser_extension/sites.local.json` | каким страницам разрешено принять пароль и где у них поля формы |
| Панель (интерфейс) | карточка + запись Vault с галочкой «Использовать этот доступ для автовхода» | какой именно логин/пароль подставлять |

## Ваши сервисы: что уже настроено и что осталось

| Сервис | Адрес для карточки | Статус |
| --- | --- | --- |
| MSB Activity | `https://msb-activity.meryosab.com/login` | встроен, ничего делать не нужно |
| Repair Partner Service | `https://repair-partner-service.meryosab.com/ru/login` | встроен, ничего делать не нужно |
| MSB Career (админка) | `https://msb-career.meryosab.com/admin/login/` | встроен, ничего делать не нужно |
| Внутренний сервис | `http://192.168.8.81:8085/login` | встроен, нужен один ключ в `vault.env` |

Важные детали по этим адресам:

- **MSB Activity.** `https://msb-activity.meryosab.com/dashboard` — это страница
  *после* входа, автовход по ней невозможен. Карточка должна вести на `/login`.
- **MSB Career.** Ссылку вида `https://msb-career.meryosab.com/admin/login/?next=/admin/`
  сервер отклонит из-за параметра `?next=`. В карточку пишите
  `https://msb-career.meryosab.com/admin/login/` — после входа Django сам
  отправит вас в `/admin/`. Форма админки Django стандартная
  (`username`, `password`, скрытый `csrfmiddlewaretoken`), адаптеру подходит.
- **Внутренний сервис `192.168.8.81:8085`.** `http://192.168.8.81:8085/` и
  `/dashboard/` — это страницы *после* входа; адрес формы входа
  `http://192.168.8.81:8085/login` уже встроен (`vault_control/autologin.py` и
  `browser_extension/sites.json`, запись с `allow_insecure: true`). Осталось
  включить переключатель в `vault_control/vault.env`:

  ```text
  VAULT_AUTOLOGIN_ALLOW_PRIVATE_HTTP=1
  ```

  Без него сервис показывается на `/vault/` в списке пропущенных значений, а
  карточка не получает «⚡ Автовход». **Пароль при этом идёт по сети открытым
  текстом** — любой, кто слушает ваш сегмент, его увидит. Разрешение работает
  только для частных адресов (`192.168.x.x`, `10.x.x.x`, `172.16–31.x.x`,
  `127.x.x.x`, `localhost`) и только для IP или `localhost`: частное доменное
  имя не принимается, потому что может резолвиться куда угодно. Как только
  поставите сервису TLS (reverse proxy), ключ можно вернуть в `0`.

## Шаг 1. Сервер: разрешить адрес

В `vault_control/vault.env` добавьте точные адреса страниц входа через запятую
(можно в несколько строк):

```text
VAULT_AUTOLOGIN_SITES=https://crm.example.com/login,https://hr.example.org/signin
```

Правила, которые проверяет сервер (`vault_control/autologin.py`):

- только `https://`; `http://` отклоняется, кроме частных адресов при
  `VAULT_AUTOLOGIN_ALLOW_PRIVATE_HTTP=1` (пароль идёт по сети открытым текстом);
- адрес **точный**: без `*`, без `?параметров`, без `#якоря`, без логина/пароля в URL;
- порт можно указывать явно (`https://crm.example.com:8443/login`);
- похожие домены (`crm.example.com.evil.test`) не проходят.

Изменения в `vault.env` подхватываются без перезапуска. Если значение задано
настоящей переменной окружения (systemd, docker), она имеет приоритет — тогда
процесс нужно перезапустить. Список и пропущенные некорректные значения видны
на странице `/vault/`.

## Шаг 2. Расширение: разрешить страницу

```bash
cd quick_access_center/browser_extension
cp sites.example.json sites.local.json
```

В `sites.local.json` укажите те же адреса. Файл не попадает в Git.

```json
{
  "sites": [
    {"name": "CRM", "login_url": "https://crm.example.com/login"},
    {
      "name": "Портал с нестандартной формой",
      "login_url": "https://portal.example.ru/auth",
      "username_selector": "input[name='USER_LOGIN']",
      "password_selector": "input[name='USER_PASSWORD']",
      "submit_selector": "button[name='Login']"
    }
  ]
}
```

Селекторы не обязательны: без них адаптер сам ищет обычную форму. Дальше:

1. `chrome://extensions/` → значок ⟳ на расширении (перечитать `sites.local.json`).
2. Откройте главную страницу панели `/`, нажмите значок расширения и
   **«Подключить открытую панель»**. Chrome спросит доступ к адресу панели и к
   сайтам из списка — подтвердите. В попапе у каждого сервиса появится ✅.

Без разрешения браузера расширение сообщит «не выдан доступ к этому сервису» и
вкладку с паролем не откроет.

## Шаг 3. Карточка и доступ

1. «Добавить блок» → в поле ссылки вставьте адрес **точно** как в списках.
2. На карточке нажмите **🔐**, войдите в Vault, добавьте логин/пароль сервиса и
   отметьте **«Использовать этот доступ для автовхода»**.
3. На главной странице у карточки появится **«⚡ Автовход»**. Пока Vault
   разблокирован, клик по карточке открывает сайт и отправляет форму входа.

## Что должно быть на стороне самого сервиса

Это то, что нужно проверить или поправить в своих сервисах, чтобы вход
срабатывал сразу, без подбора селекторов:

1. **Точный адрес формы входа.** В список и в карточку вписывайте адрес той
   страницы, где стоит форма. Если сервис редиректит `/login` → `/account/login`,
   указывайте финальный адрес: страница входа с параметрами или якорем не
   принимается.
2. **HTTPS с доверенным сертификатом.** Для внутренней сети поставьте reverse
   proxy с сертификатом (Let's Encrypt через DNS-01 либо mkcert и установленный
   в системе корневой сертификат). По `http://` пароль не передаётся.
3. **Обычная HTML-форма**, а не только JS-обработчик:
   - `<form method="post">` с `action` на тот же домен (или пустым);
   - ровно **одно** поле `<input type="password">`;
   - **одно** поле логина типа `text`, `email` или `tel`;
   - поля не `disabled`, не `readonly`, не `hidden`.
4. **Добавьте атрибуты автозаполнения** — самый надёжный вариант, селекторы тогда
   не нужны:

   ```html
   <form method="post" action="/login">
     <input type="text" name="username" autocomplete="username" required>
     <input type="password" name="password" autocomplete="current-password" required>
     <button type="submit">Войти</button>
   </form>
   ```

   Подходят и понятные имена `username`/`login`/`email`. Если полей пароля
   несколько (например, форма смены пароля на той же странице) — задайте
   `password_selector`.
5. **Без CAPTCHA и без обязательного второго фактора на первом шаге.**
   Расширение не обходит 2FA и не решает капчу: оно заполнит логин и пароль, а
   код придётся ввести руками.
6. **Скрытые поля не трогайте.** CSRF-токены формы сохраняются, так как
   используется обычная отправка формы. Для страницы входа лучше отдать
   `Cache-Control: no-store`, чтобы одноразовый токен не приехал из кэша.
7. **Лимит попыток входа** должен допускать повтор: при неверных данных
   пользователь нажмёт карточку ещё раз.
8. **Ничего специального в cookie не требуется.** Вход выполняется в обычной
   вкладке, как если бы пользователь сам отправил форму.

Если вход у сервиса полностью нарисован JavaScript'ом и отправляется `fetch`
без реальной формы, стандартный адаптер может не подойти. Пришлите структуру
страницы входа **без паролей** — добавим адаптер под неё.

## Если сервисы ваши: сначала подумайте про SSO

Автовход с паролем — это компромисс. Если все сервисы под вашим контролем,
правильное решение «вхожу один раз и везде» — единая аутентификация:

1. Поднимите IdP: Keycloak, Authentik, Authelia, Authentik+LDAP, CAS,
   либо используйте Microsoft Entra ID / Google Workspace.
2. Подключите каждый сервис как OIDC/SAML-клиента этого IdP (в большинстве
   готовых продуктов это штатная настройка «Login with SSO»).
3. У пользователей остаётся одна учётная запись; Quick Access становится просто
   панелью ссылок — пароль сервиса хранить в Vault уже не нужно, а сессию
   продлевает IdP.
4. Там, где SSO невозможен (старые внутренние системы), используйте автовход
   по этой инструкции.

## Безопасность

- Список адресов явный, шаблоны `*` не поддерживаются ни сервером, ни расширением.
- Смена ссылки в карточке на другой домен прекращает выдачу пароля.
- Пароль живёт в памяти браузера 45 секунд и выдаётся один раз; в URL, в HTML
  карточки, в `postMessage` и на диск он не попадает.
- `vault.env` и `sites.local.json` исключены из Git; не публикуйте расширение
  вместе с ними и не присылайте пароли в обращениях.

## Быстрая диагностика

| Симптом | Причина и действие |
| --- | --- |
| На карточке нет «⚡ Автовход» | Адреса нет в `VAULT_AUTOLOGIN_SITES`, либо в Vault не отмечена галочка автовхода |
| «Расширению не выдан доступ к этому сервису» | Не подтверждено разрешение: значок расширения → «Подключить открытую панель» |
| Вкладка открылась, поля пустые | Сервиса нет в `sites.local.json`, либо адаптер не нашёл форму (несколько полей пароля, JS-форма) — задайте селекторы |
| «Сначала разблокируйте Vault» | Vault закрыт: войдите в него и нажмите карточку ещё раз |
| Вкладка открылась, но вход не выполнен | Сервис показал CAPTCHA/2FA или отверг пароль — проверьте данные и требования сервиса |
