# Автовход в свои сервисы (Chrome / Edge)

Это **локальное распакованное расширение Manifest V3** для Chrome/Edge. Оно
подставляет логин и пароль из Vault на страницах входа из **явного списка**
адресов. Встроенные адреса: `https://msb-activity.meryosab.com/login`,
`https://repair-partner-service.meryosab.com/ru/login`,
`https://msb-career.meryosab.com/admin/login/`; свои сервисы добавляются в
[`sites.local.json`](ADDING_SERVICES.md). Нужны уже запущенная панель Quick
Access и настроенный Vault. Не публикуйте расширение со своим `sites.local.json`
и `vault.env`: в исходниках паролей нет.

## Установка расширения

1. Установите/запустите Quick Access по [основной инструкции](../README.md). Для удалённого браузера панель должна открываться по **HTTPS**; обычный HTTP расширение разрешает только для `http://127.0.0.1` или `http://localhost` на **том же компьютере**.
2. В Chrome откройте `chrome://extensions/` (в Edge — `edge://extensions/`), включите **Режим разработчика / Developer mode** и нажмите **Загрузить распакованное / Load unpacked**. Выберите папку **`quick_access_center/browser_extension`**, содержащую `manifest.json`. Требуется Chrome/Edge версии **111+**.
3. Свои сервисы: скопируйте `sites.example.json` в `sites.local.json`, впишите точные HTTPS-адреса страниц входа и нажмите ⟳ на расширении. Те же адреса добавьте в `VAULT_AUTOLOGIN_SITES` в `vault_control/vault.env`.
4. Войдите в свою панель Quick Access и откройте её главную страницу `/` **без поисковых параметров**. Нажмите значок расширения и **«Подключить открытую панель»**; подтвердите доступ **к своему адресу панели и к сервисам из списка** — попап показывает их со статусом ✅/⛔. Расширение проверит маркер панели и перезагрузит вкладку. При другом адресе панели повторите подключение. Постоянного доступа «ко всем сайтам» оно не получает.

## Создание карточки и вход

1. В Quick Access нажмите **«Добавить блок»** и введите ссылку **точно** как в списке автовхода (например `https://msb-activity.meryosab.com/login`). Другие адреса, порты, поддомены, HTTP, параметры и похожие имена не допускаются.
2. Нажмите значок **🔐** на этой карточке, войдите в Vault отдельным паролем. Добавьте доступ: название, логин и пароль *для этого сервиса*; поставьте галочку **«Использовать этот доступ для автовхода»** и сохраните. Если записей несколько, отметьте **ровно одну** — новое выделение снимает прежнее. **Не отправляйте нам пароли.**
3. Вернитесь на главную страницу. У карточки появится **«⚡ Автовход»**. Пока Vault разблокирован, **нажмите карточку** (или кнопку «Открыть» в её окне): расширение откроет новую вкладку сервиса, заполнит и отправит форму. Если Vault закрылся или истёк срок сессии, войдите в него снова и **повторно нажмите карточку**; первый клик не отправляет пароль. Без расширения карточка просто открывает обычную страницу входа.
4. Чтобы выключить автовход, уберите галочку в записи Vault или удалите запись. Обычное открытие ссылки останется работать.

## Защита и ограничения

**Внимание к прежнему архиву:** он всё ещё доступен в истории Git и содержал ключи и конфигурацию. Если эти файлы могли видеть другие люди, смените пароли целевых сервисов и ключи доступа перед использованием автовхода; ротация ключа шифрования Vault с сохранением записей требует отдельной миграции (см. [основной README](../README.md#старый-архив)).

- Расширение выдаёт пароль **только** по клику на отмеченную карточку, после основной авторизации, разблокировки Vault и проверки CSRF. Сервер повторно проверяет точный адрес сайта; смена URL карточки на чужой домен прекращает выдачу пароля. Секрет **не** включается в ссылку, URL-параметры, HTML карточки, сообщения странице (`postMessage`) или локальное постоянное хранилище расширения.
- Пароль передаётся расширению через изолированный скрипт страницы Quick Access и ждёт в памяти браузера (`chrome.storage.session`) для новой вкладки. **Через 45 секунд выдача запрещена**; будильник браузера удаляет запись (если браузер задержит будильник, получить пароль всё равно не удастся). После одной выдачи или закрытия вкладки запись удаляется. Пароль неизбежно появляется в форме **самого целевого сайта** — доверяйте только его настоящему HTTPS-адресу.
- Список адресов хранится в service worker (`sites.json` + `sites.local.json`); страница спрашивает разрешение у расширения и не может ни прочитать список, ни расширить его. Контент-скрипт ставится только на разрешённые страницы входа.
- Адаптер распознаёт обычную форму **POST** с единственным полем пароля и полем логина, которая отправляется на тот же origin. Скрытые поля CSRF целевого сайта сохраняются. Если форма изменена, вход уже выполнен, есть 2FA/CAPTCHA, разрешения заблокированы или сайт отверг пароль, вкладка остаётся открытой для ручного входа; расширение **не обходит** второй фактор. Для нестандартной формы задайте селекторы в `sites.local.json`. Реальный вход нужно проверить в вашем браузере со **своими** данными — в репозитории тесты используют только вымышленные учётные данные.
- Требования к самим сервисам (HTTPS, структура формы, атрибуты полей, 2FA) и вариант с единым входом через SSO описаны в [ADDING_SERVICES.md](ADDING_SERVICES.md).

## Проверка без секретов

```bash
cd quick_access_center
node --test browser_extension/tests/*.test.mjs
.venv/bin/python -m unittest discover -s tests -q  # Windows: .venv\\Scripts\\python.exe
```

Node.js нужен только для тестов расширения, для работы расширения в Chrome/Edge — нет. Если кнопка подключения сообщает «нет открытой панели», сначала войдите в Quick Access и откройте главную страницу `/`. Если Vault разблокирован в **другой вкладке**, обновите главную страницу; если форма сервиса поменялась, предоставьте её структуру **без пароля** для доработки адаптера. Никогда не отправляйте пароли, cookies или сессионные ключи в отчётах об ошибках.
